# 图像 OCR 与视频视觉帧推理

## 依赖的底层工具 (Required Tools)
- `analyze_local_image`: (必须从 MCP Server 获取) 用于处理**本地图片文件**。读取图片绝对路径，进行 OCR 识别、布局分析或空间推理（如下棋）。
- `analyze_youtube_video_visually`: (必须从 MCP Server 获取) 用于处理**外部 YouTube 视频链接的视觉内容**。它会自动下载视频并截帧，用于解答依靠听取字幕无法解答的问题（如画面中有几只动物、是什么颜色等）。

## 标准作业流程 (SOP)
1. **意图判别与选路**：
   - 检查用户的提问，判断是否属于“纯视觉任务”。
   - 如果用户要求分析下棋走法、解读图片上的分数公式，强制使用 `analyze_local_image`。
   - 如果用户提供了一段 YouTube 视频，且询问“画面上有几只鸟”、“他的衣服是什么颜色”，这属于视觉任务，强制调用 `analyze_youtube_video_visually`。
2. **精确提问 (Query Formulation)**：
   - 给视觉工具传入的 `query` 必须极其明确。例如：“这张图片上所有的分数是什么？请以逗号分隔列表返回” 或 “画面中同时出现的鸟类最多有几只？”
3. **调用执行与自我纠错 (Self-Correction)**：
   - 发送工具调用后，仔细阅读视觉模型返回的观察结果。
   - 如果结果提示路径错误或视频下载失败，检查你的入参是否带有多余的空格或字符。
   - ⚠️ **如果此前你错误地调用了字幕抓取工具 (`fetch_youtube_transcript`) 并得到了无用信息，你应该立刻意识到你需要的是“眼睛”而不是“耳朵”，立刻转向调用 `analyze_youtube_video_visually`**。
4. **最终交付**：将视觉模型返回的确切结果直接整合进你的最终报告。

## 绝对红线 (What NOT to do)
- 🚫 **绝对禁止**大语言模型凭空“想象”图像和视频中的长相。你没有视觉，一切必须基于工具返回的文本结果。
- 🚫 **绝对禁止**在遇到需要截帧看画面的 YouTube 视频时调用 `fetch_youtube_transcript`。
- 🚫 **绝对禁止**尝试使用 Python 沙盒 (`execute_python_code`) 自己去写 `cv2` 脚本显示图片，系统环境是无头的，无法展示弹窗，必须使用上述专属 MCP 工具。
- 🚫 **绝对禁止过度拆分视觉任务**：当用户要求“按图片中的空间顺序”提取混合元素（如分数、公式、及其答案）时，Supervisor **必须将用户的原始请求一字不差地作为 query 直接透传给视觉工具**，让视觉模型一次性完成“提取+计算+排序”。绝对禁止强行拆分为“先提取列表，再用 Python 计算”，这会彻底破坏图片元素的物理空间出现顺序！
