# 多模态音视频解析与信息提取

## 依赖的底层工具 (Required Tools)
- `transcribe_audio_file`: (必须从 MCP Server 获取) 用于处理**本地音频文件**。将本地文件绝对路径传入，通过 ASR 模型转录并提取核心要素。
- `fetch_video_transcript`: (必须从 MCP Server 获取) 用于处理**外部网络视频链接（支持任意平台）**。将视频 URL 传入，自动抓取字幕并提取信息。
- 
## 标准作业流程 (SOP)
1. **识别媒体类型与路径**：
   - 检查任务目标，明确是本地音频文件还是外部视频链接。
   - 若是本地文件，务必确保从上下文中提取到文件的**绝对路径**。
   - 若是外部视频链接，先使用 `search_exact_url` 搜索到准确的 URL。
2. **制定提取策略 (Extraction Query)**：明确你究竟想从这个音视频里获取什么（例如：“提取音频中提及的所有蔬菜名称并按字母排序”、“视频中那个人对‘Isn't that hot?’的回答是什么”）。将这个明确的要求写在 `extraction_query` 参数中。
3. **调用相应的 MCP 工具**：
   - 本地音频（mp3/wav等） -> 强制调用 `transcribe_audio_file`。
   - YouTube 视频链接 -> 强制调用 `fetch_video_transcript`。
4. **评估返回结果 (Self-Correction)**：
   - 检查工具返回的结果。如果返回了报错（如文件不存在、URL无效、无可用字幕），你需要立刻分析原因，修正文件路径或 URL 后重试。
   - **特殊情况（视觉短板）**：如果你发现 YouTube 工具返回了报错提示“该问题需要视觉分析”（比如题目要求数视频里有几只鸟），说明单纯依靠字幕无法解答。此时应停止尝试抓取字幕，转而考虑使用 Python 沙盒工具 (`execute_python_code`) 配合图像视觉模型截帧处理。
5. **最终交付**：将工具提取回来的精确文本内容，严格按照用户最初要求的格式（如逗号分隔、特定排序）写入最终报告中。

## 绝对红线 (What NOT to do)
- 🚫 **绝对禁止**你自己（大语言模型）凭空猜测音频或视频里说了什么。你没有听觉和视觉，一切信息必须依赖工具返回的文本。
- 🚫 **绝对禁止**在遇到本地音频文件时调用 `fetch_youtube_transcript`，或者对 YouTube 链接调用 `transcribe_audio_file`。工具职责必须严格隔离。
- 🚫 **绝对禁止**将巨大的音视频二进制流或 Base64 编码作为文本强行塞入工具的参数中，工具只需要文件路径或 URL 字符串。
- 🚫 **绝对禁止**随意改写、缩减或主观翻译工具提取回来的关键要素（如配料表、人名、数字），必须保持绝对忠实于音视频的原文含义。
- 🚫 **绝对禁止**在提取成分、名称或名词时擅自剥离修饰语或形容词！
